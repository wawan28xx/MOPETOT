⚠️ 2. Kekurangan & Kelemahan Saat Ini (Current Gaps)
A. Analisis Statis Masih Berbasis Regex (Belum Ada Data-Flow / Taint Tracking)
- Kondisi Saat Ini: Scanner saat ini mencari string match via regex (Pattern Matching).
- Kekurangan: Belum bisa mendeteksi apakah data dari luar (Intent, Deep Link, query params) mengalir ke sink berbahaya seperti:
- WebView.loadUrl(untrustedUrl) $\rightarrow$ XSS / Intent Scheme Hijacking
- Runtime.getRuntime().exec(untrustedCmd) $\rightarrow$ Command Injection
- ContentProvider.openFile() $\rightarrow$ Path Traversal / Arbitrary File Read
- addJavascriptInterface(obj, "bridge") pada target SDK rendah $\rightarrow$ RCE.
B. Belum Ada Verifikasi Kunci Otomatis (Live Key Verification)
- Kondisi Saat Ini: Ketika menemukan AIzaSy... (Google API Key) atau AKIA... (AWS Key), scanner hanya menandai sebagai temuan.
- Kekurangan: Di bug bounty, unrestricted/sensitive key yang bernilai bounty (P1–P3) adalah yang memiliki akses data atau billing, sedangkan Google Map API key publik sering berstatus Informational / Not Applicable. Belum ada fitur auto-ping/checker untuk membuktikan exploitability kunci tersebut.
C. Kedalaman Analisis iOS / IPA Masih Tertinggal Dibanding Android
- Kondisi Saat Ini: Android sudah memiliki decompilation Java/Smali lengkap (jadx, apktool), sedangkan iOS baru sebatas parsing Info.plist dan ekstraksi string Mach-O (rabin2).
- Kekurangan: Belum ada ekstraksi:
- Class-dump (Objective-C runtime / Swift symbol demangling).
- Analisis App Transport Security (ATS) exceptions.
- Entitlements extraction (aps-environment, keychain-access-groups).
- Hardcoded URL/Secret di dalam file .nib / compiled asset catalogs.
D. Rules Kriptografi & Insecure Coding Masih Minim
- Belum ada rule SAST untuk mendeteksi:
- Mode enkripsi lemah: AES/ECB/PKCS5Padding (ECB mode mudah didekripsi polanya).
- Hardcoded IV/Key: new SecretKeySpec("1234567812345678".getBytes(), "AES").
- Insecure Random: Penggunaan java.util.Random alih-alih SecureRandom untuk token sesi.
- Insecure TrustManager: TrustAllCerts / ALLOW_ALL_HOSTNAME_VERIFIER (Bypass SSL bawaan app).
- Mutable PendingIntent: Android 12+ flag FLAG_MUTABLE tanpa explicit component.
E. Format Export Laporan Masih Terbatas
- Saat ini baru mendukung download format Markdown (.md).
- Belum ada export PDF, JSON SARIF (standar industri untuk GitHub Security/GitLab CI), atau template khusus HackerOne / Bugcrowd / Intigriti format.

🧠 1. Apa itu Droid LLM Hunter (DLH)?
Droid LLM Hunter adalah scanner keamanan Android khusus yang mengkombinasikan Static Analysis (SAST Regex) dengan Kecerdasan LLM (Large Language Model) untuk memvalidasi vulnerabilitas tingkat logika dan menghasilkan Proof of Concept (PoC) / Exploit otomatis.
🌟 2. Keunggulan & Fitur Kunci Droid LLM Hunter
┌─────────────────────────────────────────────────────────────────────────────┐
│                       DROID LLM HUNTER SCAN WORKFLOW                        │
├─────────────────┬─────────────────┬──────────────────────┬──────────────────┤
│ 1. Decompile    │ 2. Smart Filter │ 3. Context Injection │ 4. LLM & PoC Gen │
│ (JADX + Apktool)│ (Regex Pattern) │ (Smali Call Graph)   │ (Auto Exploit)   │
└─────────────────┴─────────────────┴──────────────────────┴──────────────────┘
A. Two-Stage Hybrid Architecture (Hemat Biaya Token)
- Stage 1 (Local Regex Filter): Memindai kode lokal secara instan (0 token) menggunakan detection_pattern di file YAML (misal: PendingIntent + FLAG_MUTABLE / 33554432). File yang tidak cocok langsung dibuang.
- Stage 2 (LLM Context Verifier): Hanya file yang lolos Stage 1 yang dikirim ke LLM untuk memastikan apakah ada sanitasi atau benar-benar rentan.
B. Smali Call Graph Builder (core/call_graph.py)
- Membaca file .smali untuk memetakan hubungan pemanggilan fungsi (invoke-* -> Lclass;->method()).
- Ketika suatu file rentan dianalisis, DLH menyuntikkan konteks siapa yang memanggil fungsi ini (Caller) dan fungsi apa yang dipanggil (Callee) ke prompt LLM agar AI paham alur data secara utuh.
C. Auto-Exploit & PoC Generator (config/prompts/exploit_prompt.txt)
- Tidak hanya melabeli bug, DLH meminta model LLM khusus (bisa dipisah dari model scanner) untuk membuat Payload / Command Eksploitasi siap pakai (misal: adb shell am start -a ..., exploit HTML WebView XSS, PoC broadcast).
D. Multi-Provider LLM & Content-Addressed Caching
- Mendukung 7 provider: Ollama (Lokal/Offline), Groq, OpenAI, Gemini, Claude, OpenRouter, dan Router9.
- Response Cache (output/.dlh_cache/): Menyimpan hash dari (model + prompt + code). Jika scan terputus atau dijalankan ulang pada file yang sama, hasilnya instan dan 0 token cost.
E. OWASP MASVS Enrichment (masvs_mapping.json)
- Setiap rule (ada 27+ rules YAML) langsung dipetakan ke standar OWASP MASVS ID, deskripsi risiko, dan link referensi resmi.
⚠️ 3. Kekurangan & Keterbatasan Droid LLM Hunter
1. Hanya Mendukung Android APK:
- DLH tidak mendukung iOS (IPA), React Native Hermes (.hbc), Flutter (libapp.so), Unity (IL2CPP), atau file biner native murni.
2. Ketergantungan Kuat pada API LLM:
- Jika token habis, kena rate limit, atau LLM mengalami halusinasi, scan bisa gagal/terhambat.
3. Database Secret Masih Sedikit:
- DLH hanya memiliki rule rahasia dasar (hardcoded_secrets.yaml), tidak memiliki regex database rahasia selengkap tools Anda (87+ rules cloud, crypto, DB, JWT, gateway).
4. Tidak Memiliki Web Dashboard Terintegrasi:
- CLI output dan JSON report; Web dashboard-nya dibuat di repository terpisah (dashboard-report-dlh).

1. 🔍 Desain Opsi A: Intent Parameter Extractor (poc_engine.py)
Saat backend menganalisis file Java/Smali dari komponen yang exported="true":
- Regex / AST Scanner mengekstrak:
- String Extras: getIntent().getStringExtra("token") $\rightarrow$ --es "token" "EXPLOIT_PAYLOAD"
- Int Extras: getIntExtra("id", 0) $\rightarrow$ --ei "id" 1337
- Boolean Extras: getBooleanExtra("is_admin", false) $\rightarrow$ --ez "is_admin" true
- URI Data Query: getIntent().getData().getQueryParameter("redirect_url") $\rightarrow$ -d "myapp://auth?redirect_url=https://evil.com"
- Hasil di Web UI: Tombol ADB PoC otomatis terisi parameter asli aplikasi target, bukan sekadar dummy.
2. 💉 Desain Opsi B: Tombol "Generate Frida Bypass Script" (One-Click)

Backend akan mengagregasikan hasil deteksi (dari APKiD, Manifest, dan Code Scanning) dan meracik script Frida .js komprehensif yang memuat:
1. Universal SSL Pinning Bypass: OkHttp3 (CertificatePinner), TrustManagerImpl, NetworkSecurityConfig, Webview Client.
2. Root / Jailbreak Detection Bypass: Hook File.exists (/system/bin/su), Build.TAGS (test-keys), RootBeer library bypass.
3. Biometric Bypass: Hook BiometricPrompt.AuthenticationCallback.onAuthenticationSucceeded().
4. Targeted Crypto Dumper: Hook otomatis fungsi AES/DES (Cipher.doFinal, SecretKeySpec) jika scanner menemukan rule Crypto di aplikasi tersebut.
5. UI Interaktif: Pengguna bisa langsung melihat script di browser, menyalinnya (Copy Frida Script), atau mengunduhnya sebagai bypass_hooks.js.
